# 稜線リファレンスアーキテクチャ 概要書（v0.3-draft）

## これは何か

地方中小企業の熟練者が持つ暗黙知（五感の判断、目利き、人と文脈の記憶）を、AIエージェントを含む業務システムへ転換するための参照実装（リファレンスアーキテクチャ）です。

製品ではなく「型」です。株式会社稜線はこの型の上で個社の仕組みを設計し、地域のITパートナーはこの型の上で運用・拡張します。型を公開するのは、中身を隠さないこと自体が、お客様と地域パートナーへの約束だからです。

## 理論的背景

知識経営のSECIモデル（野中郁次郎・竹内弘高）を土台に、暗黙知の「中身」を3つの類型で捉え直した、稜線独自の枠組みです。SECIモデルは知識が変換される「プロセス」（共同化→表出化→連結化→内面化）の理論であり、稜線の3類型は暗黙知の「中身」の分類です。両者は直交する別のフレームワークとして扱っています。

## なぜ「文書化」では渡らないのか

このアーキテクチャの形は、マニュアル化がうまくいかない三つの理由から決まっています。

**箱は渡るが、矢印は渡らない。** 手順・項目・基準値（箱）は書けます。書けないのは、この状態を見たら次はここを見る、この値がこう出たらあの手順を飛ばす、という箱と箱の間の移動（矢印）です。矢印は書き写しでは移らず、本人が書き、直され、また書く反復の中でしか生えません。だから記録の単位は結論ではなく、**どの観測からどの判断へ移ったか**でなければなりません。

**レシピは項を書くが、演算子を書けない。** 酸やミネラル感は、それ自体の味というより、他の要素の見え方を変えるものとして働きます。項の一覧という形式には、この作用を書く欄がありません。だから記述形式は、要素の羅列ではなく**要素間の関係**でなければなりません。

**一般化すると嘘になる。** 熟練者の判断は条件に縛られています。「一般には」と言い換えた瞬間に嘘になるから、本人は黙る。マニュアルは一般化を強制する形式なので、一番大事な判断ほど最初に落ちます。だから記録は一般化せず、**それが成り立つ条件（妥当スコープ）ごと**保存されなければなりません。

## 7つの設計原則

1. **対応が必要なときだけ通知** — 定期サマリーや「正常です」通知は設けない。現場の注意力を消費しない運用が標準。
2. **既存システムは読み取り専用** — 販売・生産・会計など既存の仕組みには一切書き込まない。壊さないから、試せる。
3. **いつでも撤退できる** — データは標準形式で全量返却。設定はコードの外。囲い込みをしない構造を最初から。
4. **最終判断は人間** — AIは稽古相手・壁打ち相手。「人がまだAIに反論できているか」を定点観測する。
5. **地域で回せる軽さ** — 小規模なITパートナーが運用できる構成と手順書（ISO20000水準の軽量版）を含む。
6. **観測は逐語で残し、解釈と分ける** — 現場の言葉は現場の言葉のまま保存する。整形・要約・用語統一は別レイヤーで行い、元の記録を上書きしない。後から解釈をやり直せる余白を残すため。
7. **当事者が動かせる深さで止める** — 原因はいくらでも深く掘れるが、成果物は、その現場の言葉で言い表せて、その現場の権限で手が打てる深さに置く。理解の深さと介入の深さは別に管理する。

## 暗黙知の3類型と、対応するエージェント

| 類型 | 内容 | エージェントの役割 |
|---|---|---|
| 官能判断型 | 五感による品質判断（香り・泡・色など）。要素の値ではなく、要素間の作用として現れる | 判断の型を学習し、ベテランの「勘」の稽古相手になる |
| 目利き・見積り型 | 経験的な評価・見積りの根拠 | 根拠を言語化し、反証と代替案を提示する |
| 関係記憶型 | 人・文脈・関係性の記憶 | 関係をグラフ化し、想起を支援する |

いずれの類型も、判断の機会が年に数回しかなく、答え合わせが季節や年の単位でしか返ってきません。高速な反復を前提にした学習の型は、ここでは働きません。

## 記録の4つの単位

1. **観測** — いつ、何を、どの条件で見たか（SOSA/SSN準拠）。数値と、現場の言葉の両方。
2. **判断の遷移** — どの観測から、どの判断へ移ったか。何を根拠とし、何を退けたか（PROV-O準拠）。結論だけを残さない。
3. **妥当スコープ** — その判断が成り立つ条件（この現場の、この年の、この材料で、この気温なら）。一般化しないための錨。
4. **聞き書きの逐語** — 熟練者の発言をそのままの語彙で。あわせて、聞き手が差し出した言葉と、返ってきた言葉を並べて記録する。返ってきた言葉が聞き手の語彙のままなら、それは本人の言葉ではない。この判別を後から行えるようにするための記録。

## 技術構成（4層＋横断的な約束）

下から上へ：現場の記録が、意味を持ち、知能に渡り、対応が必要なときだけ人に届きます。

1. **記録・接続層** — モバイル記録UI（官能評価5段階＋メモ、現場で10秒で記録）／聞き書き記録UI（逐語・妥当スコープ・聞き手の言葉との並記）／センサー入力（SOSA/SSN準拠）／読み取り専用アダプタ（既存の販売・生産・会計系へは書き込まない）
2. **データ層** — RDFストア（稜線オントロジー、SOSA/SSN・PROV-O準拠。観測だけでなく判断の遷移と妥当スコープを保持）／PostgreSQL＋pgvector（構造データ・ベクトル検索）／オブジェクトストレージ（画像・音声・文書）
3. **知能層** — オーケストレーター（エージェント間の役割分担と衝突解消、LLM APIは差し替え可能）／官能判断エージェント／目利き・見積りエージェント／関係記憶エージェント
4. **提示・運用層** — アラート通知（対応トリガーのみ）／稽古相手UI（壁打ち・反証提示、最終判断は人間）／ダッシュボード・出力（標準形式エクスポート）

## 判断の三層

AIに任せる範囲を、層で切り分けます。

- **第1層：気づく** — 閾値超過や欠測の自動通知。人手を介さない。
- **第2層：候補を出す** — 診断候補、反証、代替案、過去の類似事例の提示。根拠を必ず添える。助言であり、決定ではない。
- **第3層：決める** — 判断は人間が行う。ここを自動化しない理由は、AIの精度が足りないからではありません。判断を代行された人は、判断できるようになりません。仮に代行の精度が十分でも、代行した時点で技能の継承が止まります。

同じ理由で、聞き取りそのものも自動化しません。何を掘り、どこで止め、返ってきた言葉が本人のものか——これらの判定に必要な材料は、会話の中ではなく、会話の前の下調べ（その仕事の実体、その組織の力量、その言葉が現場で通用するか）にあります。下調べを持たずに会話へ入れば判定は省略され、整った形の、中身のない記録が残ります。

全層に効く約束として、人間の最終判断ゲート、ISO27000水準のセキュリティ管理策、ISO20000水準の軽量運用プレイブック、撤退容易性、「人がまだ反論できているか」の定点観測があります。

## 名前空間

稜線オントロジーの名前空間は `https://ryousen.co.jp/ns/ryosen#` です。定義の正本（canonical）はこのリポジトリの [`ontology/ryosen-core.ttl`](../ontology/ryosen-core.ttl) にあります。

## デプロイ構成

- **最小構成（はじまりの一歩）**：国内VPS（さくら／ConoHa）＋Docker Compose。月数千円のインフラ費で全層が動く。小さく始めて、いつでもやめられる。
- **クラウド構成（伸ばすとき）**：AWS／Azureのマネージドサービスへ同じ型のまま移行。可用性・拡張性が必要になった段階で。
