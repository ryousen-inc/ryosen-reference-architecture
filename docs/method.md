# 稜線観測法（v0.4-draft）

熟練者の判断を聞き取り、記録し、受け手に渡すための進め方です。システムの型は[概要書](overview.md)にあり、本書はその上で人が何をするかを書いています。

版番号は概要書にそろえました。2026年8月に記事として公開した内容（問いの更新、差し戻しの正規化）は、本書に取り込んでいます。

## 1. これは何か

暗黙知を扱う仕事が失敗するとき、原因は答えの精度不足ではありません。壊れた問いを持ったまま、観察を回し続けてしまうことです。

熟練者に「何を手がかりに判断しているのか」と聞いても「長年の勘」としか返ってこないとき、問うべきだったのは別のことかもしれません。熟練者は選んでいたのではなく、いつも通りからのずれに気づいていただけかもしれない。そうなら、問うべきは「あなたの中の『いつも通り』は何でできているか」です。

稜線観測法は、答えを磨く前に**問いのほうを更新しつづける**ための進め方です。

## 2. 二階建てのループ

- **速い輪（登攀）** — 問いを固定したまま、答えの仮説を日々検証する。周期は日次から週次、場所は現場の中
- **遅い輪（稜線歩き）** — 問いそのものがまだ働いているかを、月次で見直す。現場を出て、その月の個別の知見を議論することを禁じた時間を持つ

同じ会議で両方を扱いません。速い輪の緊急性が必ず勝ってしまうからです。

遅い輪を回すべき合図は、速い輪の成績表の中に隠れています。

| 合図 | 速い輪の解釈 | 遅い輪の問い |
|---|---|---|
| 答えが簡単に出るようになった | 解明が進んだ | 予測できているのは、観察しやすい判断だけではないか |
| 答えが出なくなった | 聞き方を磨こう | 「判断」という枠組み自体が合っていないのではないか |
| 答えは出るのに、現場が動かない | 記述を細かくしよう | 取り出すべきは判断ではなく、判断の前にある注意の配り方ではないか |

### 差し戻しは、あるべき手戻り

個々の記述はすべて正しいのに、つなぐと矛盾することがあります。これは組み立ての失敗ではなく、切り出しの単位を前の工程で間違えていたことが、ここで初めて見えたということです。熟練者が一語で呼ぶものが、構造の上でも一つとは限りません。

前の工程への差し戻しは、例外ではなく正常な動作として扱います。

- 次に進んでよいかの審査とは別に、「いまどこにいて、差し戻しが要るか」を見る時間を持つ
- 差し戻しには、必ず**再合流の条件**を添える。条件のない差し戻しは、際限なく戻り続ける
- 同じ箇所への差し戻しが三回目になったら、方法そのものの欠陥を疑う

## 3. 七つの問いフレーム

意思決定、パターン認識、状況認識、スキル・ルール・知識、分散認知、知識構造、転移。認知工学と知識構造論から借りたこの七つを、正しい理論としてではなく「問いを生み出す装置」として使います。

| フレーム | 中心の問い |
|---|---|
| 意思決定 | どの手がかりを、どう重みづけて選んでいるか |
| パターン認識 | どんな典型を持ち、何をずれとして検知しているか |
| 状況認識 | いつ・どこに注意を配り、次に何を見込んでいるか |
| スキル・ルール・知識 | 身体化・手順・推論のどの層で走っているか |
| 分散認知 | 判断は道具・帳面・同僚にどう分かれているか |
| 知識構造 | この知識の境界と粒度は、他とつながるか |
| 転移 | 書かれたものに触れた人の中に、何ができたか |

どれが当たるかは、現場に入るまで分かりません。空振りが続いたら乗り換えます。

## 4. 抽出型と生成型

すでに熟練者の中にある判断を、言葉にして取り出す仕事を**抽出型**と呼んでいます。一方、判断が正しかったかどうかを確かめる仕組みが現場にまだ無く、言葉が生まれる前に、確かめられる仕組みのほうを先に作る必要がある場合があります。こちらを**生成型**と呼びます。

聞き書きだけでは届かないのは後者です。

## 5. 何を掘るか — 符号のついた抽象語

熟練者の発言を聞いたまま書き起こすと、ある種類の言葉が混じっています。「そろそろだな」「今日は機械の機嫌が悪い」「今年のもろみは、いい顔をしている」。

| 言葉の形 | 例 | 中身 |
|---|---|---|
| 具体的で、良し悪しの符号がある | 「この客は値段で切られる」 | すでに判断になっている。記録でき、引き継げる |
| 抽象的で、符号がない | 「忙しい」「普通」 | 何も運んでいない。掘る先がない |
| 抽象的で、符号がある | 「そろそろだ」「素直じゃない」 | **まだ形になっていない判断が畳まれている** |

掘るのは三つ目です。熟練者は何かを見て、何かと比べて、良いか悪いかまでは決めています。何を見て何と比べたかは、本人の中でも開いていません。

- 負の符号だけでなく、正の符号も同じように拾います。「いい顔をしている」も、畳まれた判断です
- この種の言葉は、要約したときに真っ先に落ちます。感情語は情報ではないと見なされるからです。聞いたまま書く理由の一つがここにあります

### 状態を問題に変える

「あせっている」「抱え込んでしまう」のような言葉は、本人の中では「そういう状態」として置かれています。状態には解き方がありません。期待と現状の差として書き直すと、解ける形になります。

ワークショップでは、多くの参加者が「問題として考えると解決方法があることに驚いた」と話しました。解決方法が見つかったのは、本人が賢くなったからではなく、問題の形にしたら最初からそこにあったからです。

## 6. 記録する

### 逐語で残す

現場の言葉は、現場の言葉のまま残します。整形・要約・用語の統一は別の層で行い、元の記録を上書きしません（概要書の設計原則6）。

### 読みを先に封じ、後で照合する

判断の前に、これから起きることの予測（読み）を一行で書き、確定させます。確定した読みは書き換えません。起きたことは聞いたまま・見たままを追記し、後で読みと突き合わせて「合っていた／半分／違った」を付けます。

- 結果を知った後に読みを直すと、すべてが当たった記録になり、何も学べません
- 何を見落としたかは、外れた回にしか残りません
- 読みを書いて封じた時点で、本人にとってそれは感想ではなく仮説になります。判断した自覚のなかった熟練者が、ここで初めて自分の判断を持ちます
### 採った案にも理由を書く

人は、退けた案には理由を書きます（「それは無理がある」）。ところが採った案には理由を書きません。採用は自明に見えるからです。そして前の工程で検討した分岐は、次の工程に持ち越されず、選ばれた枝だけが転記されます。

- 退けた案だけでなく、採った案にも理由を求めます
- 前の工程の分岐を、下流まで運ぶ欄を用意します

### 差し出した言葉と、返ってきた言葉を並べる

聞き手が先に言葉を差し出すことがあります。うまくいけば、それを踏み台に相手自身の言葉が上がってきます。うまくいかなければ、相手は聞き手の言葉をそのまま飲んで返してきます。普通に記録すると、この二つは区別がつきません。

並べて書いておけば、後から検査できます。返ってきた言葉が聞き手の語彙のままなら、それは本人の言葉ではありません。相手自身の言葉に変わっていれば、相手の中で何かがつながった印です。この欄は、聞き取りがうまくいったかどうかの判定器を兼ねています。

## 7. 開く

### 聞かずに並べる

「なぜそう思ったのか」と聞くと、答えは一般論になります。何十年分を一言でまとめようとするので、どの一日でもない答えが返ってきます。

代わりに、予測と結果が離れた回を、日付と事実を付けて並べます。「この日のこの判断は、何を見ていたのか」と、その日の具体が目の前にある状態で振り返ると、熟練者はその日の具体で話しはじめます。開くのは本人で、記録は並べるだけです。

### たとえで名前を引き出す（検証中）

熟練者が参照している知識の集まりは、本人に見えていません。直接「何を見ていたか」と聞いても出てきません。ところが、別の領域で構造の似たものを差し出すと、「それと同じだ」と言えることがあります。

- 似ているものを見分ける力は、自分の中の集まりを直接見る力より先にあります
- 差し出したたとえに、相手が自分の言葉で応じたとき、その言葉が、相手の中の集まりの名前になります
- **聞き手が持っている知識の集まりの数と幅が、相手の集まりに名前を付けられる範囲を決めます**。下調べとは、相手の領域を知ることだけでなく、相手の領域と構造が似た別の領域を複数持っておくことです
- たとえの候補を出すことはAIにも手伝えます。どれを差し出すかは、相手の反応を見ながら聞き手が選びます

## 8. 受け手の設計

熟練者への聞き取りをいくら積んでも、出てくるものが精緻になるだけで、受け手が何を必要としているかは見えません。受け手の側の設計が別に要ります。

### 職能が、たどる経路を決める

同じ記入用紙を使っても、どの箱とどの箱の関係を確かめるかは、受け手の職能によって違います。ワークショップでは、開発の経験がある人は「実現方法」と「成果指標」を直接結び、開発をしない人はその組を検討すらしませんでした。能力の差ではなく、身についた癖の差です。**どの線を引いたかより、どの線を見なかったかのほうが、その人の職能をよく表します。**

### 箱は渡っても、矢印は自然には生えない

仕事で同じ枠組みを何年も使い、役にも立てている人でも、箱の間を自分で行き来する判断（矢印）は、自然には身につきませんでした。箱が渡ることと、矢印が生えることは別です。

### 成果指標から、問題の定義へ戻る

成果指標を考えている途中で、問題の定義のほうが間違っていたと分かることがあります。ワークショップでも、成果指標を詰めているうちに本当に解きたかった問題が掘り出され、問題の定義まで戻ってやり直した例がありました。

この逆向きの経路は、失敗ではなく正規の手戻りとして扱います。概要書の「チェックポイント」は、この手戻りをシステムの側で支えるものです。

### 仕組みかどうかを、本人が確かめる一問

「解決の仕組み」の欄には、次の一問を添えます。

> この仕組みは、隣の問題にも使えるか。

使えなければ、それは仕組みではなく実装です。仕組みは、目の前の問題より広い範囲に効くはずだからです。定義で教えると渡らない箇所なので、検査の形で本人に気づいてもらいます。

### 30秒で説明してもらう（検証中）

できあがった一枚を、第三者に説明してもらいます。自由に一度、次に30秒で。30秒の説明で何が落ちるかに、構造の理解が表れます。

### 言葉にした本人が、変わる

言語化は、中立な取り出し作業ではありません。言葉にした瞬間に、本人の自己理解が変わります。ワークショップの参加者からは「うすうす分かっていたが、言葉にできていなかったことが言葉になった」という声が繰り返し出ました。若手に起きることは、熟練者にも起きるはずです。型は、取り出す道具であると同時に、取り出された側を変える道具でもあります。

## 9. 場で仕上げる

記録を開くのは、熟練者・若手・経営者が同じ記録を前に座る場です。若手の成長段階（守・破・離）は、システムではなくこの場が、記録をもとに合意します。詳しくは概要書の「場」と「守破離は、場が記録から読む」を参照してください。

## 10. 公開していないもの

プローブ質問のセット、フレーム乗り換えの判断表、記録の書式などを含む実務用プレイブックは、稜線認定パートナー向けに限定して提供しています。
